### 📚 **Create your applications using modern JavaScript**

Benefit from the latest technology updates to rapidly prototype and develop your applications.

<hr>

### ✨ **Integrate technologies you already use**

Use popular frameworks and tools right out-of-the-box. Focus on building features instead of configuring disparate components yourself.

<hr>

### 💻 **Build apps for any device**

Use the same code whether you’re developing for web, iOS, Android, or desktop for a seamless update experience for your users.

# 🚀 Quick Start

On your platform, use this line:

```shell
> npx meteor
```

🚀 To create a project:

```shell
> meteor create
```

☄️ Run it:

```shell
cd my-app
meteor
```

# 🤝 Help maintain Meteor

Try a reported issue in your app, review a change in a package you know, or improve a guide you found hard to follow. [Find an area to help with](MAINTAINERS.md).

Core Maintainers choose the areas they look after and help prioritize issues and reviews. The Technical Steering Committee makes the final call on major changes and publishes official releases. [How Meteor is governed](GOVERNANCE.md)

* [Core development guide](DEVELOPMENT.md)
* [Contribution guidelines](CONTRIBUTING.md)

# 🤝 Help with an upcoming release

For the goals behind each release and what comes next, see the [Meteor roadmap](https://docs.meteor.com/about/roadmap.html).

<!-- #region release-collaboration -->

Start with an unassigned issue or an open pull request in a release milestone. When you [triage a bug report](https://github.com/meteor/meteor/blob/devel/ISSUE_TRIAGE.md#bugs), share the steps that reproduce it and the Meteor version you tested. For a regression, include the last version that worked. You can also help maintainers close an issue by linking the fix or the original report for a duplicate. For a superseded PR, link its replacement.

The focus badges show related issues and PRs across milestones. To see how the labels work together, follow [an installer bug from report to release](https://github.com/meteor/meteor/blob/devel/LABELS.md#an-example-from-a-bug-report-to-its-release). If you find another fix that fits the release, share your test results on its issue or PR. The patch row links to open bugs in areas covered by the [Meteor 3.6 release notes](https://docs.meteor.com/history#v3-6-0-2026-11-10).

Know one of the areas below? Try a PR in your app, tell the author what you found, and check back when a revision is ready. The core development guide shows [how to test a contributor’s branch](https://github.com/meteor/meteor/blob/devel/DEVELOPMENT.md#testing-a-fork-branch).

### 🌱 Make your first contribution

These are unassigned issues marked `good first issue`. Pick one that interests you and check the latest comments and linked PRs. Leave a note with what you’d like to try, or ask on the issue if you could use a hand getting started.

| Find an issue | A first step |
| --- | --- |
| [![Good first issues: all areas](https://img.shields.io/badge/good_first_issue-all_areas-3e5fa3)][first-issue-all] | Pick an issue you can try locally and share what you find. |
| [![Good first issues: docs](https://img.shields.io/badge/good_first_issue-docs-3e5fa3)][first-issue-docs] | Follow the documented steps and point out where the instructions and the result differ. |
| [![Good first issues: cli](https://img.shields.io/badge/good_first_issue-cli-3e5fa3)][first-issue-cli] | Run the command in the report and compare its output with the expected behavior. |
| [![Good first issues: types](https://img.shields.io/badge/good_first_issue-types-3e5fa3)][first-issue-types] | Try a small TypeScript example and show which line should pass or fail type checking. |

When you’re ready to share your change, the contribution guide walks you through [submitting a pull request](https://github.com/meteor/meteor/blob/devel/CONTRIBUTING.md#submitting-pull-requests).
