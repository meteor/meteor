## 8: Routing

Right now, our whole application lives at a single URL (`/`): `mainContainer` uses an <code v-pre>{{#if isUserLoggedIn}}</code> check to decide whether to show the task list or the login form, and there is no way to link to a separate page.

In this step, we will use [`ostrio:flow-router-extra`](/tutorials/routing/routing) to give our application dedicated URLs:

- `/` — the main task list
- `/login` — the sign-in page
- `/about` — an about page with a navigation link in the header

### 8.1: Verify Flow Router Extra is installed

If you created your project with `meteor create --blaze`, `ostrio:flow-router-extra` is already listed in `.meteor/packages`. If you started from an older template without it, add it now:

```shell
meteor add ostrio:flow-router-extra
```

### 8.2: Turn `mainContainer` into a layout

With `ostrio:flow-router-extra`, a layout template renders the shared chrome of your app (like the header bar) and uses <code v-pre>{{> yield}}</code> as the placeholder where the active route's page template is rendered.

Let's split `imports/ui/App.html` into three templates:

- `mainContainer` — the layout with the top bar, navigation links (<code v-pre>{{pathFor}}</code>), and <code v-pre>{{> yield}}</code>
- `tasksPage` — the task form, filter button, and task list
- `aboutPage` — a second page to navigate to

Because `FlowRouter` renders the layout into `document.body` automatically, we also remove the static `<body>` wrapper tag from `imports/ui/App.html`:

::: code-group

```html [imports/ui/App.html]
<template name="mainContainer">
    <div class="app">
        <header>
            <div class="app-bar">
                <div class="app-header">
                    <h1>📝️ To Do List {{incompleteCount}}</h1>
                    <nav class="app-nav">
                        <a href="{{pathFor 'tasks'}}">Tasks</a>
                        <a href="{{pathFor 'about'}}">About</a>
                    </nav>
                </div>
            </div>
        </header>

        <div class="main">
            {{> yield}}
        </div>
    </div>
</template>

<template name="tasksPage">
    {{#if isLoading}}
        <div class="loading">loading...</div>
    {{/if}}

    <div class="user">
        {{getUser.username}} 🚪
    </div>

    {{> form }}

    <div class="filter">
        <button id="hide-completed-button">
            {{#if hideCompleted}}
                Show All
            {{else}}
                Hide Completed
            {{/if}}
        </button>
    </div>

    <ul class="tasks">
        {{#each tasks}}
            {{> task}}
        {{/each}}
    </ul>
</template>

<template name="aboutPage">
    <div class="about">
        <h2>About Simple Todos</h2>
        <p>Built with Meteor 3, Blaze, and Flow Router Extra.</p>
    </div>
</template>

<template name="form">
    <form class="task-form">
        <input type="text" name="text" placeholder="Type to add new tasks" />
        <button type="submit">Add Task</button>
    </form>
</template>
```
:::

Update `imports/ui/App.js` so that the task subscription, `ReactiveDict` filter state, helpers, and events belong to `Template.tasksPage`, while `incompleteCount` remains on `Template.mainContainer`. When the user clicks the username to log out, redirect them to `/login` with `FlowRouter.go('login')`:

::: code-group

```js [imports/ui/App.js]
import { Meteor } from 'meteor/meteor';
import { Template } from 'meteor/templating';
import { ReactiveDict } from 'meteor/reactive-dict';
import { FlowRouter } from 'meteor/ostrio:flow-router-extra';
import { TasksCollection } from '../api/TasksCollection';
import '/imports/api/TasksMethods.js';
import './App.html';
import './Task.js';
import './Login.js';

const HIDE_COMPLETED_STRING = 'hideCompleted';
const IS_LOADING_STRING = 'isLoading';

const getUser = () => Meteor.user();
const isUserLoggedIn = () => Boolean(getUser());

const getTasksFilter = () => {
  const user = getUser();
  const hideCompletedFilter = { isChecked: { $ne: true } };
  const userFilter = user ? { userId: user._id } : {};
  const pendingOnlyFilter = { ...hideCompletedFilter, ...userFilter };

  return { userFilter, pendingOnlyFilter };
};

Template.mainContainer.helpers({
  incompleteCount() {
    if (!isUserLoggedIn()) {
      return '';
    }

    const { pendingOnlyFilter } = getTasksFilter();
    const incompleteTasksCount = TasksCollection.find(pendingOnlyFilter).count();
    return incompleteTasksCount ? `(${incompleteTasksCount})` : '';
  },
});

Template.tasksPage.onCreated(function tasksPageOnCreated() {
  this.state = new ReactiveDict();

  const handler = Meteor.subscribe('tasks');
  this.autorun(() => {
    this.state.set(IS_LOADING_STRING, !handler.ready());
  });
});

Template.tasksPage.events({
  'click #hide-completed-button'(event, instance) {
    const currentHideCompleted = instance.state.get(HIDE_COMPLETED_STRING);
    instance.state.set(HIDE_COMPLETED_STRING, !currentHideCompleted);
  },
  'click .user'() {
    Meteor.logout(() => {
      FlowRouter.go('login');
    });
  },
});

Template.tasksPage.helpers({
  tasks() {
    const instance = Template.instance();
    const hideCompleted = instance.state.get(HIDE_COMPLETED_STRING);
    const { pendingOnlyFilter, userFilter } = getTasksFilter();

    if (!isUserLoggedIn()) {
      return [];
    }

    return TasksCollection.find(
      hideCompleted ? pendingOnlyFilter : userFilter,
      { sort: { createdAt: -1 } }
    ).fetch();
  },
  hideCompleted() {
    return Template.instance().state.get(HIDE_COMPLETED_STRING);
  },
  isLoading() {
    return Template.instance().state.get(IS_LOADING_STRING);
  },
  getUser() {
    return getUser();
  },
});

Template.form.events({
  'submit .task-form'(event) {
    event.preventDefault();

    const { target } = event;
    const text = target.text.value;

    Meteor.callAsync('tasks.insert', {
      text,
      createdAt: new Date(),
    });

    target.text.value = '';
  },
});
```
:::

### 8.3: Redirect after logging in

In `imports/ui/Login.js`, navigate to the `tasks` route once `Meteor.loginWithPassword` succeeds:

::: code-group

```js [imports/ui/Login.js]
import { Meteor } from 'meteor/meteor';
import { Template } from 'meteor/templating';
import { FlowRouter } from 'meteor/ostrio:flow-router-extra';
import './Login.html';

Template.login.events({
  'submit .login-form'(e) {
    e.preventDefault();

    const { target } = e;
    const username = target.username.value;
    const password = target.password.value;

    Meteor.loginWithPassword(username, password, (error) => {
      if (!error) {
        FlowRouter.go('tasks');
      }
    });
  },
});
```
:::

### 8.4: Define the routes

Now register the routes in `client/main.js`. We use an enter trigger (`requireLogin`) on the `/` route so unauthenticated visitors are redirected to `/login`:

::: code-group

```js [client/main.js]
import { Meteor } from 'meteor/meteor';
import { FlowRouter } from 'meteor/ostrio:flow-router-extra';
import '../imports/ui/App.js';

const requireLogin = (context, redirect) => {
  if (!Meteor.userId() && !Meteor.loggingIn()) {
    redirect('/login');
  }
};

FlowRouter.route('/', {
  name: 'tasks',
  triggersEnter: [requireLogin],
  action() {
    this.render('mainContainer', 'tasksPage');
  },
});

FlowRouter.route('/login', {
  name: 'login',
  action() {
    this.render('mainContainer', 'login');
  },
});

FlowRouter.route('/about', {
  name: 'about',
  action() {
    this.render('mainContainer', 'aboutPage');
  },
});
```
:::
